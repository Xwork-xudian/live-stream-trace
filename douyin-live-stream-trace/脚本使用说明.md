# 抖音直播间推流端识别工具集

通过多种方式识别直播间使用的第三方推流软件（数字人/AI无人直播工具）。

## 示例直播间（仅供参考）

- 直播间地址: https://live.douyin.com/376389454958
- room_id: 7640506484396411698
- 已知 app_id: 932313（推流端内部 ID，非开放平台 ID）

> ⚠️ 以上为示例数据，使用时请替换为目标直播间信息。

## 快速开始

```bash
# 安装依赖
pip install requests

# Playwright 浏览器鉴权（推荐，自动处理 a_bogus 签名）
pip install playwright && playwright install chromium

# 一键全角度分析（推荐）
python analyze_room.py --room 376389454958 --playwright --format both

# 含双流异常检测
python analyze_room.py --room 376389454958 --playwright --format both --detect-dual-stream

# 分析本地 FLV 文件
python parse_flv_metadata.py --file captures/flv_sample_20260516_190950.flv

# 分析在线直播间
python flv_analyzer.py --room-id 376389454958

# 监控直播间开播
python monitor_reflow.py --room-id 7640506484396411698

# 生成统一分析报告
python unified_report.py
```

## 脚本详细说明

### 共享模块

#### config.py — 全局配置

集中管理所有常量，避免各脚本重复定义。

| 配置项 | 值 | 说明 |
|--------|-----|------|
| `ROOM_ID` | `7640506484396411698` | 内部房间 ID |
| `WEB_ROOM_ID` | `376389454958` | Web 房间号 |
| `API_TIMEOUT` | 15 秒 | API 请求超时 |
| `POLL_INTERVAL` | 30 秒 | monitor 轮询间隔 |
| `DOWNLOAD_MAX_BYTES` | 262144 (256KB) | FLV 流最大下载量 |
| `SOFTWARE_PATTERNS` | 10 条 | 从 `mappings/software_patterns.json` 加载 |
| `CDN_PATTERNS` | 13 条 | 从 `mappings/cdn_patterns.json` 加载 |
| `RTMP_BINARY_KEYWORDS` | 27 个 | RTMP 抓包二进制搜索关键词 |

**API 端点**:
- `REFLOW_URLS`：`/webcast/room/reflow/info/`
- `ENTER_URLS`：`/webcast/room/web/enter/`

**多域名支持**: 脚本自动尝试 `live.douyin.com` 和 `webcast-hl.amemv.com` 两个 API 域名。当第一个域名返回 404/10011 时自动 fallback 到下一个。

#### amf0.py — AMF0 解析器

统一 AMF0 协议解析，支持 13 种类型：

| 类型 | Marker | 说明 |
|------|--------|------|
| Number | 0x00 | 64 位浮点 |
| Boolean | 0x01 | 布尔值 |
| String | 0x02 | UTF-8 字符串 |
| Object | 0x03 | 键值对（带结束标记 0x09） |
| Null | 0x05 | 空值 |
| Reference | 0x07 | 引用（指向已解析值） |
| ECMA Array | 0x08 | 关联数组 |
| Strict Array | 0x0A | 索引数组 |
| Date | 0x0B | 日期时间 + 时区 |
| Long String | 0x0C | 长字符串（4 字节长度） |
| XML Document | 0x0F | XML 文档 |
| Typed Object | 0x10 | 带类名对象 |
| AMF3 Switch | 0x11 | AMF3 切换标记 |

关键函数：
- `parse_amf_value(data, offset)` — 通用 AMF0 值解析
- `parse_flv_header(data)` — FLV 文件头解析
- `parse_flv_script_tag(data)` — FLV Script Tag 解析
- `extract_encoder_hints(metadata)` — 从 onMetaData 提取编码器线索（大小写不敏感）
- `ci_get(d, key, default)` — 大小写不敏感 + `onMetaData.` 前缀查找

安全防护：Object/ECMA Array 循环最大 8192 次迭代，防止畸形数据导致无限循环。

#### network.py — HTTP 工具

| 函数 | 说明 |
|------|------|
| `http_get(url, params, headers, timeout, retries, backoff, proxies)` | GET 请求，支持指数退避重试 |
| `download_bytes(url, headers, max_bytes, timeout, retries, proxies)` | 流式下载，限制最大字节数 |
| `download_response_headers(url, headers, timeout, proxies)` | HEAD 请求，获取 CDN/响应头信息 |

重试策略：默认 3 次重试，指数退避（1s → 2s → 4s），429/5xx 自动重试。

### 采集脚本

#### 0. analyze_room.py — 一键全角度分析（推荐入口）

统一编排脚本，只需提供 Web 房间号即可自动完成全部采集和分析流程，适合快速获取目标直播间的完整画像。

```bash
# 推荐: Playwright 鉴权 + 全格式报告
python analyze_room.py --room 376389454958 --playwright --format both

# 含双流异常检测
python analyze_room.py --room 376389454958 --playwright --format both --detect-dual-stream

# 详细日志模式
python analyze_room.py --room 376389454958 --playwright -v

# 已知内部 room_id 时跳过解析
python analyze_room.py --room 376389454958 --internal-id 7640506484396411698

# 仅生成文本报告
python analyze_room.py --room 376389454958 --playwright --format text
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--room` | **必填** | Web 房间号（URL 中的数字，如 `376389454958`） |
| `--playwright` | 否 | 启用 Playwright 浏览器鉴权（推荐，自动处理 a_bogus） |
| `--detect-dual-stream` | 否 | 启用双流异常检测（多清晰度/多模式/跨协议对比） |
| `--capture-probes` | 否 | 额外采集 `gift/list`、`room/info`、`ranklist/audience` 原始 JSON |
| `--internal-id` | — | 内部 room_id（提供后跳过自动解析） |
| `--output-dir` | `captures/` | 采集数据输出目录 |
| `--report-dir` | `reports/` | 报告输出目录 |
| `--format` | `both` | 报告格式: `html`, `text`, `both` |
| `-v, --verbose` | 否 | 详细日志模式 |

**8 步自动流程**:

| 步骤 | 描述 | 条件 |
|------|------|------|
| Step 0 | Playwright 浏览器鉴权 → cookies + web/enter 拦截 | 需要 `--playwright` |
| Step 1 | 解析 Web 房间号 → 内部 room_id | 必须执行 |
| Step 2 | reflow/info API 单次采集（字段树 + 关键字段） | 需要 room_id |
| Step 3 | web/enter API → 流地址 + 画质选项 | 复用 Step 0/1 缓存 |
| Step 4 | 下载 FLV 样本（256KB） | 仅直播中 |
| Step 5 | FLV 元数据解析 → 编码器指纹 + 推流软件识别 | 需要 FLV 样本 |
| Step 6 | 双流异常检测（可选） | 需要 `--detect-dual-stream` |
| Step 7 | Capture-First 探针采集（可选） | 需要 `--capture-probes` |
| Step 8 | 生成统一报告（文本 + HTML） | 始终执行 |

**部分失败容错**: 各步骤独立执行，某步失败不影响后续步骤。最终汇总表显示每步成功/失败状态。

**输出文件**: 与各独立脚本相同（flv_sample、onmetadata、reflow、stream_url_struct、unified_report 等），全部保存到 `captures/` 和 `reports/`。

新增原始证据落盘：
- `captures/playwright_enter_{web_room_id}_{ts}.json`
- `captures/playwright_cookies_{web_room_id}_{ts}.json`
- `captures/room_resolution_{web_room_id}_{ts}.json`
- `captures/stream_url_raw_{ts}.json`
- `captures/session_manifest_{ts}.json`
- `captures/dual_stream_samples/{ts}/*.flv`
- `captures/dual_stream_manifests/{ts}/*.{m3u8,mpd}`

#### Capture-First 探针

首版只做原始采集与 `session_manifest` 登记，**不接** `unified_report.py`，**不做**字段提炼或 `reflow/info` 差异分析。

```bash
python gift_list_probe.py --room <Web房间号> --internal-id <内部room_id> -v
python room_info_probe.py --room <Web房间号> --internal-id <内部room_id> --cookies "<cookie字符串>" -v
python ranklist_probe.py --room <Web房间号> --internal-id <内部room_id> --anchor-id <主播ID> --cookies "<cookie字符串>" -v
```

- `gift_list_probe.py`：`gift/list/`，原始 JSON 落盘，要求 `internal_room_id`
- `room_info_probe.py`：`room/info/`，原始 JSON 落盘，要求 cookies，优先使用 `internal_room_id`；**当前在已结束房间上可能返回空体，应视为受限能力**
- `ranklist_probe.py`：`ranklist/audience/`，原始 JSON 落盘，要求 `internal_room_id`、`anchor_id`、cookies；**当前在已结束房间或缺少稳定主播上下文时可能返回空体，应视为受限能力**

通过 `analyze_room.py --capture-probes` 时，3 个 probe 会作为可选 step 运行，并把产物登记到 `session_manifest`。

已知边界：
- `gift_list_probe.py` 已验证在线成功并可落盘。
- `room_info_probe.py` 与 `ranklist_probe.py` 当前更适合在直播中房间、且具备更完整上下文时验证成功路径；已结束房间上的空响应不视为主流程故障。

**Room ID 解析流程**:
1. 调用 `web/enter` API 从 Web 房间号提取内部 room_id
2. 失败时尝试 `reflow/info` API（使用 webcast-hl.amemv.com）
3. 均失败则标记为"未知"，后续步骤按需跳过

## 映射表维护

- `mappings/field_descriptions.json`：字段中文说明，`monitor_reflow.py` 与 `unified_report.py` 共用
- `mappings/software_patterns.json`：推流软件识别正则，`config.py` 加载后向下游暴露 tuple 列表接口
- `mappings/cdn_patterns.json`：CDN / 第三方推流域名识别关键词，`flv_analyzer.py` 与 `unified_report.py` 共用

维护约束：
- 保持 JSON 有效 UTF-8 编码
- `software_patterns.json` 每项必须包含 `pattern` 和 `name`
- `cdn_patterns.json` 每项必须包含 `keyword` 和 `name`
- 采用 first-match-wins；越具体的关键词应排在越前面

修改后建议执行：
```bash
python -c "from config import SOFTWARE_PATTERNS, CDN_PATTERNS; print(len(SOFTWARE_PATTERNS), len(CDN_PATTERNS))"
python parse_flv_metadata.py --glob "..\\..\\captures\\*.flv" -v
```

#### 1. flv_analyzer.py — FLV 直播流在线分析

从观众端拉取直播 FLV 流，解析编码器信息、onMetaData 和 CDN 特征。

```bash
# 分析指定房间
python flv_analyzer.py --room-id 376389454958

# 直接分析 FLV 流 URL
python flv_analyzer.py --url "https://pull-flv-l11.douyincdn.com/..."

# 分析本地 FLV 文件
python flv_analyzer.py --file captures/flv_sample_20260516_190950.flv

# 详细日志
python flv_analyzer.py --room-id 376389454958 -v
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--room-id` | `376389454958` | Web 房间号 |
| `--url` | — | 直接指定 FLV 流地址 |
| `--file` | — | 本地 FLV 文件路径 |
| `--output-dir` | `captures/` | 输出目录 |
| `-v, --verbose` | 否 | 详细日志模式 |

**输出文件**:
- `captures/flv_sample_{ts}.flv` — FLV 流样本
- `captures/flv_report_{ts}.txt` — 文本分析报告
- `captures/flv_analysis_{ts}.json` — 结构化 JSON 结果（含 encoder_hints、fingerprint）
- `captures/onmetadata_{ts}.json` — 完整 onMetaData 导出
- `captures/onmetadata_readable_{ts}.txt` — onMetaData 可读文本
- `captures/stream_url_struct_{ts}.json` — 流 URL 结构化解析（在线模式）

**JSON 结构**:
```json
{
  "type": "flv_analysis",
  "timestamp": "20260516_190950",
  "room_id": "376389454958",
  "stream_url": "https://...",
  "header": {"format": "FLV", "version": 1, "has_audio": true, "has_video": true},
  "metadata": {},
  "encoder_hints": {},
  "fingerprint": {},
  "resolution": "540x960",
  "video_codec": "H.264",
  "audio_codec": "AAC",
  "stream_url_structure": "stream_url_struct_{ts}.json",
  "raw_file": "flv_sample_{ts}.flv",
  "report_file": "flv_report_{ts}.txt"
}
```

**可获取的信息**:
- FLV 版本号、音视频轨道信息
- 视频编码器（H.264/AVC、H.265/HEVC、AV1）
- 音频编码器（AAC）、采样率、声道
- `onMetaData` 中的 `encoder`、`metadatacreator` 等字段
- HTTP 响应头中的 CDN/推流服务商信息
- 流 URL 域名特征（如 `third` 表示第三方推流）

**多域名拉流地址获取**:
- 自动按 `live.douyin.com` → `webcast-hl.amemv.com` 顺序尝试 `webcast/room/web/enter/`
- 当首个域名返回 10011、404 或无响应时，自动切换到下一个域名继续获取流 URL

**注意事项**:
- **必须在直播进行中运行**，下播时无法获取流地址
- 部分直播间可能需要登录 Cookie
- 抖音 API 可能需要 `msToken`/`a_bogus` 鉴权参数

| `-v, --verbose` | 否 | 详细日志模式 |

**输出文件**:
- `captures/reflow_{room_id}_{ts}.json` — 完整 API 响应

#### 4. rtmp_capture.py — RTMP 推流抓包分析

使用 tshark 抓取 RTMP 协议流量（TCP 1935），提取 flashVer、tcUrl、app 等字段。

```bash
# 实时抓包（管理员权限运行）
python rtmp_capture.py --interface eth0 --duration 30

# 分析已有 pcap 文件
python rtmp_capture.py --pcap captures/rtmp_capture_20260516.pcap

# 指定过滤 IP
python rtmp_capture.py --filter-ip 1.2.3.4 --duration 60
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--interface, -i` | `eth0` | 网络接口 |
| `--duration, -d` | 30 秒 | 捕获时长 |
| `--filter-ip` | — | 过滤目标 IP |

### 鉴权与检测模块

#### auth_playwright.py — Playwright 浏览器鉴权

通过无头 Chromium 自动访问直播间页面，拦截 `web/enter` API 响应，提取浏览器 cookies 和 msToken，自动处理 `a_bogus` 签名。

```bash
# 独立测试鉴权
python auth_playwright.py 79519393944

# 在 analyze_room.py 中通过 --playwright 自动调用
python analyze_room.py --room 79519393944 --playwright
```

| 参数 | 说明 |
|------|------|
| `web_room_id` | 位置参数，Web 房间号 |
| `--visible` | 显示浏览器窗口（调试用，默认 headless） |

**前置依赖**:
```bash
pip install playwright && playwright install chromium
```

**工作原理**:
1. 启动 headless Chromium，导航到 `https://live.douyin.com/{web_room_id}`
2. 拦截 `web/enter` API 响应（包含 stream_url、room 数据）
3. 提取全部浏览器 cookies（含 httpOnly 的 ttwid）
4. 从网络请求中提取 msToken
5. 返回鉴权上下文：cookies、ms_token、stream_url_obj、room_id 等

**注意**: `a_bogus` 是每次请求独立计算的 JS 签名，无法复用。Playwright 通过让浏览器自动执行签名 JS 来完成鉴权。

#### dual_stream_detector.py — 双流异常检测

检测直播间是否存在"阴阳流"（不同用户看到不同内容）或双流推送（主路+备用路不同）。通过多维度对比实现：

1. **多清晰度对比** — 下载不同画质级别的 FLV 样本，比较编码参数
2. **双模式对比** — `need_double_stream=true` vs `false` 的流地址差异
3. **跨协议对比** — FLV vs HLS/DASH 的编码参数和 CDN 来源差异

由 `analyze_room.py --detect-dual-stream` 自动调用，也可通过 `importlib` 独立使用。

**输出文件**: `captures/dual_stream_analysis_{room_id}_{ts}.json`

**风险评分**: 0-100 分，综合编码参数差异、CDN 来源差异、画质级别数量等信号。

## API 域名说明

抖音直播接口有两个可用域名，脚本自动尝试全部：

| 域名 | 类型 | 说明 |
|------|------|------|
| `live.douyin.com` | Web 网关 | 浏览器端入口，可能需要 msToken/a_bogus |
| `webcast-hl.amemv.com` | 客户端网关 | APP 端入口，无需鉴权即可访问 reflow/info |

脚本按列表顺序依次尝试，返回有效数据则停止。当某个域名返回 404、10011 鉴权错误或无响应时，自动切换到下一个域名。

## 推荐使用顺序

### 快速分析（推荐）

```bash
python analyze_room.py --room 376389454958 --playwright --format both
```

一键完成全部采集和分析（含浏览器鉴权），适合大多数场景。

### 含双流检测

```bash
python analyze_room.py --room 376389454958 --playwright --format both --detect-dual-stream
```

额外检测阴阳流/双流替换风险。

### 分步操作

1. **后台挂载 `monitor_reflow.py`** — 持续监控，等目标直播间开播时自动抓取 reflow/info 响应
2. **开播时运行 `flv_analyzer.py`** — 立即分析拉流端的编码器和元数据信息
3. **离线分析** — `parse_flv_metadata.py` 对已有 FLV 样本做深入元数据解析
4. **生成报告** — `unified_report.py` 关联所有采集结果
5. **深入分析** — 使用目标推流工具时用 `rtmp_capture.py` 抓包提取 flashVer

## 已知限制

- `app_id: 932313` 是抖音内部直播系统 ID，不是开放平台 ID，无法通过开放平台查询归属
- `reflow/info` 在 `webcast-hl.amemv.com` 无需鉴权即可访问；`web/enter` 需要 `a_bogus` 签名（已通过 `--playwright` 自动解决）
- RTMP 抓包仅适用于本机推流场景
- 部分推流工具可能不在 `onMetaData` 中写入软件名称
- 无法看到服务端内部中转链路
- 第三方中转可能污染指纹
- 非RTMP 推流（SRT/SDK）不会被 RTMP 抓包捕获
- CDN 可能剥离部分元数据
- 双流检测仅对比 Web 端可见的画质级别，无法检测客户端 SDK 层面的阴阳流
